# #1540 — Include <sys/select.h> to get select(3), fixing the build on strict POSIX libcs

- Commit: efd8f9b3
- Verdict: SAFE

## What it changes
Adds a single line, `#include <sys/select.h>`, to `src/core/net-disconnect.c`.
This file uses `select(3)`, `fd_set`, `FD_ZERO`, and `FD_SET` (lines 124-144)
but previously relied on those symbols being pulled in transitively. POSIX-1.2024
mandates `<sys/select.h>` as the header providing these, so the explicit include
fixes the build on strict libcs (e.g. Sortix) that do not expose `select` through
other headers. Purely additive; no logic change.

## Files touched
- `src/core/net-disconnect.c`

## Release-safety findings
None — safe to release.

- `<sys/select.h>` is a standard POSIX header present on all platforms irssi
  targets (Linux, *BSD, macOS, Solaris). irssi already includes many unguarded
  `<sys/*>` headers (e.g. `network.h` includes `<sys/socket.h>`, `<netinet/in.h>`,
  `<netdb.h>`, `<arpa/inet.h>`), so this introduces no new portability assumption.
- Native Windows is not a concern: commit `96766b7f` ("Remove all WIN32 ifdefs")
  deliberately stripped the Windows build path from this very file, so there is no
  MSVC code path that would choke on `<sys/select.h>`.
- Standard headers are idempotent (include guards), so even if `<sys/select.h>`
  were already pulled in transitively on some platform, re-including it is harmless.
- No macro/type redefinition risk; no behavioral, ABI, or security implications.
