# #1403 — Exit gracefully on SIGTERM by emitting "gui exit" and quitting

- Commit: 58109aee
- Verdict: SAFE

## What it changes
Re-writes SIGTERM handling. Previously SIGTERM was handled by `sig_term()` in
`settings.c`, installed via `signal(SIGTERM, sig_term)` in `init_configfile()`.
That handler ran real work in async-signal context: it called `signal()`,
`signal_emit("command quit", ...)`, then re-`raise(SIGTERM)` to die.

The new approach:
- Adds a global flag `int sigterm_received` (core.c/core.h), mirroring the
  existing `sighup_received`.
- Installs a minimal async-signal-safe handler `sig_term()` in core.c that only
  sets `sigterm_received = TRUE`. It is wired up in `read_settings()` via the
  existing `sigaction()` loop (respecting the `ignore_signals` setting), so it is
  (re)installed at `core_init` and on every `setup changed`.
- Removes the old `sig_term()` and its `signal(SIGTERM, ...)` registration from
  settings.c.
- Both fe-text and fe-none main loops now check `sigterm_received` each
  iteration and, when set, clear it and `signal_emit("gui exit", 0)` — the same
  clean-shutdown path used by `/QUIT` and by SIGHUP-with-`quit_on_hup`.
- fe-none's `sig_exit` no longer calls `g_main_loop_quit()`; it sets
  `quitting = TRUE` and the loop is converted from `g_main_loop_run()` to a
  `while (!quitting && !reload) g_main_context_iteration(NULL, TRUE)` poll loop,
  matching fe-text's long-standing structure.
- Bumps `IRSSI_ABI_VERSION` 49 -> 50.

## Files touched
- src/common.h (ABI bump)
- src/core/core.c (new flag + handler, sigaction wiring)
- src/core/core.h (extern declaration)

## Release-safety findings
None — safe to release.

Notes considered and cleared:
- The old handler did real work (signal_emit/signal/raise) directly inside an
  async signal handler, which is undefined behavior. The new handler only sets a
  flag and defers all work to the main loop — this is strictly safer.
- `sigterm_received` is a plain `int`, not `volatile sig_atomic_t`. This is the
  only theoretical wart, but it is identical to the `sighup_received` pattern
  that has shipped for years and uses the same flag/main-loop mechanism, so it
  is not a new or regressed risk.
- No dangling references: the removed `settings.c` `sig_term` was never declared
  in a header and has no remaining callers. `grep` confirms no other use.
- The handler is installed in `read_settings()` (run at core_init and on every
  `setup changed`) and never removed, so there is no window where SIGTERM falls
  back to default termination after startup.
- fe-none loop conversion is correct: a delivered signal interrupts the blocking
  `g_main_context_iteration` poll (EINTR), the iteration returns, the flag is
  checked, `gui exit` is emitted, and `quitting`/`reload` end the loop. fe-text
  already used this exact poll-and-check structure for SIGHUP.
- The `gui exit` path performs the normal graceful shutdown (server quits,
  autosave via `settings.c` `sig_autosave`, session handling), so a SIGTERM'd
  irssi now disconnects/quits cleanly rather than re-raising SIGTERM to die.
- ABI bump 49->50 is appropriate (new exported symbol + behavior change) and
  forces module rebuilds, which is the intended/correct effect.
- No injection or untrusted-input surface: SIGTERM delivery is not attacker
  data, and no strings are interpolated.

## Interactions with related changes
None. The change is self-contained to signal handling and the two frontend main
loops; it reuses the pre-existing `gui exit` / `sighup_received` machinery.

## NEWS accuracy
Accurate. NEWS says "Exit gracefully on SIGTERM by emitting \"gui exit\" and
quitting," which precisely matches the implementation. (The change additionally
bumps the ABI version and refactors fe-none's loop, but those are mechanical
consequences, not a material scope difference.)
