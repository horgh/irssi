# #1597 — Update bundled scripts autoop, mail, and scriptassist

- Commit: ebdf8639
- Verdict: SAFE

## What it changes
Vendored sync (`syncscripts.sh`) pulling upstream updates for three optional
bundled Perl scripts:

- `autoop.pl` (1.10 -> 1.11): fixes a real latent bug in `load_autoops` —
  the old `if ($line !=~ /^\s*$/)` was misparsed as a numeric comparison
  (`$line != (~ m/.../)`), so the blank-line skip never worked correctly; now
  it is `!~` and a `chomp` is added.
- `mail.pl` (2.92 -> 2.93): help-text-only fix. The registered setting was
  already `maildir_mode` (`settings_add_bool('misc', 'maildir_mode', ...)`);
  the help text incorrectly said `MAILDIRMODE`/`maildirmode` and is now
  corrected to `MAILDIR_MODE`. No behavior change.
- `scriptassist.pl` (2022053100 -> 2023111700): substantial refactor. Adds
  Python-script support (detect via `Irssi::commands`, list/exec via the
  `py` command, parse a script's `IRSSI`/`__version__` with Python `ast`).
  `get_names` is rewritten to return a locked hashref instead of a positional
  list and now correctly receives the `$db` argument (the old
  `my ($sname,$db) = shift;` only assigned `$sname`, so `$db` was always
  undef). Helper accessors `get_remote_version`/`get_local_version` are
  removed and folded into `get_names`. Adds `X-Died` header checks on HTTP
  responses. Adds `use JSON::PP;` and `use Hash::Util qw(lock_ref_keys);`.

## Release-safety findings
None — safe to release.

- These scripts are installed as data files (`scripts/meson.build`,
  `install_data`), not compiled into irssi and not autoloaded. They affect
  only users who explicitly `/script load` them; they cannot break the build,
  ABI, or a default irssi session.
- All three scripts pass `perl -c` (static syntax check) cleanly.
- New dependencies `JSON::PP` and `Hash::Util` are Perl core modules
  (available with the system perl here), so the added `use` lines do not
  introduce a new external CPAN requirement for the common case.
- Injection review of the new Python path: the `py exec` snippet interpolates
  `$filename` into a single-quoted Python string. The filename comes from the
  locally-loaded irssi-python `py list` output (a single whitespace-split
  field, so no embedded newline), and `\` and `'` are escaped before
  interpolation. The Python code uses `ast.parse` + `ast.literal_eval` (no
  code execution) and emits JSON consumed via `decode_json`. Data source is
  local, not remote/attacker-controlled; no meaningful injection exposure.
- The remote (network) data path's trust model is unchanged; the change only
  adds `X-Died` failure checks (defensive, stricter) on top of existing
  `is_success` checks.
- `update_scripts`/`check_scripts` now read `local_version`/`db_version`
  which may be undef; the existing guards (`next if $local eq '' || $remote
  eq ''` and `if ($local && $remote)`) treat undef safely, matching the prior
  undef-returning behavior of the removed accessors. Worst case is a benign
  "uninitialized value" warning, not a crash.
