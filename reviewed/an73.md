# an#73, 4115e474 — Remove deprecated compile-time build options such as PERL_STATIC_LIBS, HAVE_SOCKS and USE_GREGEX

- Commit: 4115e474
- Verdict: SAFE

## What it changes
Pure dead-code / dead-option cleanup that drops compile-time switches which the meson build (the only build system in this tree after an#64 removed autotools) could never enable:

- `PERL_STATIC_LIBS`: meson always passed `-DPERL_STATIC_LIBS=0`, so all `#if PERL_STATIC_LIBS == 1` blocks in `src/perl/perl-core.c` were unreachable. They are removed, the perl bootstrap glue (`boot_Irssi_Core`, static deinit loop) is deleted, and `irssi-core.pl`'s `is_static()` is hardcoded to `0`. The `%d`/`PERL_STATIC_LIBS` placeholder is dropped from both the `irssi-core.pl` format string and the matching `g_strdup_printf(irssi_core_code, use_code)` call — they stay in sync (one `%s`, one arg).
- `HAVE_SOCKS` / `HAVE_SOCKS_H`: meson always set `HAVE_SOCKS` to false (undefined) and never defined `HAVE_SOCKS_H`. The `SOCKSinit()` calls in `src/fe-none/irssi.c` and `src/fe-text/irssi.c`, the conditional `<socks.h>` include in `network.h`, and the meson `conf.set('HAVE_SOCKS', ...)` are removed. The SOCKS docs are reworded to point at proxychains-ng.
- `USE_GREGEX` / `disable-gregex`: GRegex is hardcoded as the regex backend. The `disable-gregex` meson option is deleted, the POSIX `regex.h` fallback (`iregex-regexh.c`) is removed, `iregex.h` unconditionally typedefs `Regex`/`MatchInfo` to the GRegex types, and `src/core/meson.build` always compiles `iregex-gregex.c`.
- `HAVE_GMODULE`: meson always set it true, so `#else /* !HAVE_GMODULE */` stubs (in `modules-load.c`, `fe-modules.c`, `modules.h`) and the conditional `<gmodule.h>` include in `common.h` were dead. They are removed; GModule is now an unconditional include/dependency (it already always was a build dependency).
- `HAVE_STATIC_IRC` / `HAVE_STATIC_PERL` / `HAVE_STATIC_OTR`: never defined anywhere in the meson tree. The forward decls and `#ifdef HAVE_STATIC_*` init/deinit blocks in the two `irssi.c` files and `fe-common-irc.c` are removed, and the static-link stub files `src/irc/irc.c` and `src/fe-common/irc/irc-modules.c` are deleted.

## Release-safety findings
None — safe to release. Verified:
- Every removed `#ifdef`/`#if` branch was unreachable in the meson build: `PERL_STATIC_LIBS` was always 0, `HAVE_GMODULE` always true, `HAVE_SOCKS` always false, and `HAVE_STATIC_*`/`HAVE_SOCKS_H` were never set anywhere in the tree (grep across the merge tree finds no setter; they were autotools-only leftovers, and autotools was removed in an#64).
- The perl format-string change is consistent: the generated `irssi_core_code` now has exactly one `%s` and no `%d`, matching the single-arg `g_strdup_printf`. A mismatch here would be a crash risk; it is correct.
- No dangling callers of the deleted stub functions (`irc_init`, `irc_deinit`, `fe_irc_modules_init/deinit`, `SOCKSinit`) remain — their only callers were inside the removed `#ifdef` blocks. The `src/irc/core/meson.build` reference to `irc.c` is the unrelated real `src/irc/core/irc.c`, not the deleted stub.
- No remaining POSIX-regex usage (`regcomp`/`regexec`/`regex_t`/etc.) after `iregex-regexh.c` deletion; the GRegex implementation (`iregex-gregex.c`) is now always built.
- GModule was already an unconditional build dependency, so making `<gmodule.h>` unconditional introduces no new portability requirement.
- No injection/security surface: the perl `eval`/`g_strdup_printf` data flow is unchanged except for dropping a constant integer argument.

## NEWS accuracy
Accurate. The line names PERL_STATIC_LIBS, HAVE_SOCKS, and USE_GREGEX and frames it as removing deprecated compile-time options, which matches the diff. One scope note (not a NEWS error): the change also removes the user-facing `disable-gregex` meson option and the `regex.h` fallback entirely, so a build can no longer opt out of GRegex. This is an intentional, project-consistent removal (GRegex has been the default for years) and is covered by "such as ... USE_GREGEX".
