# #1566 — Fix two memory leaks when creating a main window with not enough space

- Commit: 599448af
- Verdict: SAFE

## What it changes
In `mainwindow_create()`, `rec` is allocated with `g_new0()` at the top of the
function. On the two "not enough space" early returns (one for the non-right
split path, one for the right-split path), the function previously returned
`NULL` without freeing `rec`, leaking the just-allocated `MAIN_WINDOW_REC`. The
change adds `g_free(rec)` immediately before each of those two `return NULL`
statements (each return is now wrapped in a brace block).

## Files touched
- src/fe-text/mainwindows.c

## Release-safety findings
None — safe to release.

The fix is correct and complete:
- `rec` is allocated via `g_new0(MAIN_WINDOW_REC, 1)`; only scalar fields are
  assigned before the two return points, so no nested allocations are leaked and
  `g_free(rec)` is the right cleanup.
- At the freed points `rec` has not yet been inserted into the `mainwindows`
  list and is not referenced after being freed, so there is no use-after-free
  or double-free.
- All other exits from the function fall through to
  `g_slist_append(mainwindows, rec)` (which takes ownership) and are unaffected.
- The `NULL`-return contract is unchanged; both callers already handle it
  (`gui-windows.c` falls back to the active main window;
  `mainwindows.c:1405` prints "window too small" and returns).
- No security/injection surface; no behavior, default, or ABI change on the
  success path.
