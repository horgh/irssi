# an#80, ed4ec313 — Abort the meson build (and bump the required meson version) when run in an autotools-configured tree

- Commit: ed4ec313
- Verdict: SAFE

## What it changes
Three logical changes in the meson build (the merge `ed4ec313` brings in `cfd421a9`; the content is present in master, reformatted by sibling pr1611):

1. Bumps the minimum meson from `>=0.49` to `>=0.53` (and updates INSTALL / README docs and the CI matrix to `==0.53.2` and `<0.63.0`).
2. Imports the `fs` module and adds an early guard: if any of `config.status`, `irssi-version.h`, `default-config.h`, `default-theme.h`, `src/perl/irssi-core.pl.h`, `src/perl/perl-signals-list.h`, or `irssi-config.h` exists, it calls `error('this tree has been configured with autotools, cannot proceed')`.
3. Makes `check:` explicit on several `run_command()` calls: `check: false` on the best-effort `mkdir`/`ln` symlink setup (expected to fail harmlessly on reruns), and `check: true` on the perl-introspection and `syntax.pl` commands (so they fail loudly instead of silently yielding empty values).

## Release-safety findings
None — safe to release.

- The `fs` module, `fs.exists()`, and the `run_command(check:)` kwarg are all available at the new `>=0.53` floor, and the CI matrix actually exercises `==0.53.2`, so the minimum is tested.
- No false positives for a clean meson build: meson `custom_target`/`configure_file` write the generated headers (`irssi-version.h`, `irssi-config.h`, `default-config.h`, `default-theme.h`, `src/perl/*.h`) into the build directory, while `fs.exists()` with a relative path resolves against `meson.current_source_dir()`. These names appear in `.gitignore` precisely because they were historically generated *in-tree* by autotools, which is exactly the leftover state the guard is meant to detect.
- The guard only triggers on a tree polluted by a prior in-source autotools configure; in that case aborting with a clear message is strictly safer than the previous behavior of attempting a confused/broken build. This is a defensive improvement, not a regression.
- Adding `check: true` to the perl/syntax commands can newly hard-abort configure if perl introspection genuinely fails, but on a working perl toolchain these succeed; failing loudly is the intended robustness fix and is consistent with newer meson's default. No injection surface: all `run_command` arguments are fixed literals or build-system-controlled paths, not user input.
