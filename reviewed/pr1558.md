# #1558 — Remove const qualifiers in fe-text terminfo for better Darwin support

- Commit: 44494551
- Verdict: SAFE

## What it changes
Drops the `const` qualifier from string-pointer fields in two terminfo data
structures:
- `terminfo-core.c`: the `TERMINFO_REC` struct's `ti_name` and `tc_name`
  members (`const char *` -> `char *`). These hold the static `tcaps[]`
  capability-name table.
- `terminfo-core.h`: all the `TI_*` capability string pointers in
  `struct _TERM_REC` (`TI_smcup`, `TI_cup`, `TI_setaf`, `TI_sgr0`, `TI_smkx`,
  etc.) change from `const char *` to `char *`.

This is purely a type-qualifier relaxation so the pointers can be passed to
platform terminfo/termcap functions (`tparm`, `tigetstr`) whose prototypes on
Darwin/macOS declare plain `char *` parameters rather than `const char *`,
which newer clang treats as a hard error rather than a warning. No code logic,
no field layout, and no allocation/free behavior is altered.

## Files touched
- src/fe-text/terminfo-core.c
- src/fe-text/terminfo-core.h

## Release-safety findings
None — safe to release.

Verification of the things that matter for a const-removal:
- No new writes through the now-non-const pointers. The `TI_*` capability
  strings are only read (passed to `tparm`, `g_string_append`, `g_strcmp0`).
  The only mutation is `current_term->TI_rmcup = NULL;` in
  `term-terminfo.c:120`, which reassigns the pointer itself — already legal
  under `const char *` and unaffected by this change.
- No new frees of read-only memory. `TI_*` capability pointers reference
  terminfo's own static storage (from `tigetstr()`) and are never freed.
  `terminfo_core_deinit`/`terminfo_colors_deinit` free only `TI_normal`,
  `TI_fg`, `TI_bg` (and elements), which are heap-allocated via
  `g_strdup`/`g_string_free_and_steal` and were never `const`.
- `tcaps[]` `ti_name`/`tc_name` are string literals in a `static` array;
  `ti_name` is read-only via `tigetstr/tigetnum/tigetflag`, `tc_name` is never
  referenced. Nothing writes to or frees them, so the literals remain
  effectively read-only despite the non-const type.
- `TERM_REC` is an internal struct (not part of any installed/public ABI), so
  there is no ABI concern.
- No injection or security surface: only type qualifiers change.
