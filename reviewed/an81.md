# an#81, e300fee9 — Add a new PUBNOTICES message level to separate public channel notices from private notices

- Commit: e300fee9
- Verdict: MINOR

## What it changes
Adds a new message level `MSGLEVEL_PUBNOTICES` to distinguish notices sent to a
channel (public) from notices sent to a user (private).

- `src/core/levels.h`: inserts `MSGLEVEL_PUBNOTICES = 0x0000010` between
  `MSGLEVEL_NOTICES` and `MSGLEVEL_SNOTES`, shifting every higher bit up by one
  and widening `MSGLEVEL_ALL` from `0x03fffff` to `0x07fffff`. The high flag
  bits (`NOHILIGHT`, `NO_ACT`, `NEVER`, `LASTLOG`, `HIDDEN`, `RESERVED*`,
  `FORMAT`) are unchanged.
- `src/core/levels.c`: adds `"PUBNOTICES"` to the level-name table in the
  matching position.
- `src/common.h`: bumps `IRSSI_ABI_VERSION` 46 -> 47 (correct, since the enum
  values that modules compile against changed).
- `src/perl/common/Core.xs`: exports a new `MSGLEVEL_PUBNOTICES()` accessor.
- `src/fe-common/irc/fe-irc-messages.c`: reworks `sig_message_irc_notice` and
  `sig_message_own_notice` so public/cnotice notices are tagged
  `MSGLEVEL_PUBNOTICES` (private notices stay `MSGLEVEL_NOTICES`), and the public
  notice now renders with a nick prefix via the new `notice_public` format.
- Default settings updated to keep prior behavior visible: `autocreate_query_level`
  gains `NOTICES`, `activity_msg_level` becomes `PUBLIC NOTICES`.
- `src/fe-common/core/formats.c`: adds `MSGLEVEL_PUBNOTICES` to
  `NOT_LINE_START_LEVEL`.
- `module-formats.c` / `themes/default.theme` / `docs/help/in/levels.in`: new
  `notice_public`/`pubnotice` formatting and help text.
- `src/fe-text/meson.build`: adds `default_config_h` and `default_theme_h` as
  build dependencies of the irssi executable (build-ordering fix).

## Release-safety findings
- Memory leak (MINOR): in `sig_message_irc_notice`, the public-notice branch
  (src/fe-common/irc/fe-irc-messages.c:326-329) allocates `nickmode` via
  `channel_get_nickmode()` and passes it to `printformat`, but never frees it.
  `channel_get_nickmode` always returns a heap allocation (even the empty
  string), and `printformat` does not take ownership — every other call site in
  this file frees the result (e.g. lines 64, 140). This leaks a few bytes for
  every public channel notice received. Bounded, no crash/UB; still present at
  current HEAD. Not a release blocker, but worth fixing.

- ABI break is handled correctly: inserting the new bit renumbers all higher
  `MSGLEVEL_*` values, which is why `IRSSI_ABI_VERSION` was bumped. Levels are
  persisted to config and logs by name, not by numeric value (see
  bits2level/level2bits and settings_add_level), so existing user configs and
  logs are not silently misinterpreted. The Perl `MSGLEVEL_*` constants are
  generated from the C enum at build time, so they stay correct. No hardcoded
  numeric level masks exist outside the enum.

- Behavior change (intended, but user-visible): notices to a channel are now
  classified `PUBNOTICES` instead of `NOTICES`. Users with existing
  ignore/log/hilight/activity rules keyed on `NOTICES` will no longer match
  public channel notices. The default-settings updates (`activity_msg_level`,
  `autocreate_query_level`) mitigate the out-of-box visibility regression, but
  custom user configs are not migrated. This matches the documented intent of
  the change and is not a defect.

- cnotice ignore target change: for context-channel ("cnotice") private notices,
  `ignore_check_plus` is now passed the parsed context channel instead of NULL,
  and such notices are now tagged `PUBNOTICES`. Consistent with treating them as
  public; no correctness problem.

- No double-free / NULL-deref issues: `context_channel` is freed on all paths
  exactly once; `channel_get_nickmode`/`channel_find` tolerate NULL channels.
  The `notice_public` format and the `pubnotice` theme abstract have matching
  arity (4 args).

- meson.build change is valid: `default_config_h`/`default_theme_h` are defined
  as global custom_targets in the top-level meson.build, so referencing them in
  fe-text is correct and improves build-ordering safety.

## Interactions with related changes
None. `src/irc/flood/flood.c` still classifies all notices under
`MSGLEVEL_NOTICES` for flood detection; it uses the symbolic constant and is
unaffected by the bit renumbering. No other consumer indexes levels by bit
position.
