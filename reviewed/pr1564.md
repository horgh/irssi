# #1564 — Adapt the PEP 440 dev version scheme in make-dist.sh

- Commit: f857f29e
- Verdict: SAFE

## What it changes
Adds one line to `utils/make-dist.sh` after the version is parsed out of
`meson.build`:

```sh
version=$(echo "$version"|perl -p -e 's/-head/.dev0/')
```

This rewrites the development version string `1.5-head` to `1.5.dev0`, which
is a valid PEP 440 development release identifier. The `version` value is then
embedded in the generated `setup.cfg` (`version = $version`) and used to form
the sdist tarball filenames (`$name-$version.tar`). Making it PEP 440
compliant prevents setuptools from rejecting/normalizing the non-conforming
`1.5-head` string when building the sdist. This is build/release tooling only;
it does not touch the irssi binary, runtime behavior, or ABI.

## Files touched
- utils/make-dist.sh

## Release-safety findings
None — safe to release.

- The transformation is correct: `1.5-head` becomes `1.5.dev0`. For an actual
  release version (e.g. `1.5.0`) the `-head` pattern does not match, so the
  substitution is a no-op and the real release tarball naming is unaffected.
- No injection concern: `$version` originates from `meson.build` parsed by
  perl, not from external/attacker input, and the value is only passed through
  `echo` into another perl process. perl is already a hard dependency of this
  script (used to parse name/version and MANIFEST.in), so no new dependency or
  portability regression is introduced. `perl -p -e` is portable.
- The script runs under `set -e`; the new line is a plain command substitution
  that will not fail for the expected inputs.
- `make-dist.sh` is invoked in CI (check.yml, solarisvm.yml, voiddocker.yml);
  the change makes the dist build more robust there rather than less.
