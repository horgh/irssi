# #1576 — Fix the Solaris GitHub Actions test by detecting the third argument type of puts

- Commit: 216715bc
- Verdict: SAFE

## What it changes
Adds detection for SVR4/Solaris systems where `tputs`'s third argument is
typed `int (*)(char)` instead of the more common `int (*)(int)`.

- `meson.build`: The textui terminfo link check is restructured. The original
  `if not cc.links(simple)` is rewritten as `if cc.links(simple) { ok } else
  {...}` (a logically equivalent inversion with branches swapped). All link
  checks gain `args : '-pedantic-errors'`, which turns the
  incompatible-function-pointer-type warning into a hard error so a mismatched
  `putchar` signature makes the probe fail rather than silently link. A new
  third fallback compiles a program passing an `int (*)(char)` callback
  (`char_putchar`); if that links, it sets both `NEED_CURSES_H` and a new
  `TPUTS_SVR4` define. The terminal `error('could not link terminfo')` is
  preserved as the final else.
- `src/fe-text/term-terminfo.c` and `src/fe-text/terminfo-core.c`: Each defines
  a `putc_arg_t` macro (`char` when `TPUTS_SVR4` is set, otherwise `int`) and
  changes the local `term_putchar` parameter from `int` to `putc_arg_t`, so the
  callback signature matches what `tputs` expects on the detected platform.
- `.github/workflows/solarisvm.yml`: CI-only; appends `|| echo N:$?` to each
  prepare step so a failing package step no longer aborts the job.

## Release-safety findings
None — safe to release.

- The meson condition inversion is logically equivalent to the original and
  only adds a new fallback before the existing `error()`. No previously-working
  configuration loses its path: on standard ncurses/glibc, `putchar` is
  `int (*)(int)`, so the first probe still links cleanly even with
  `-pedantic-errors`, takes the `# ok` branch, and leaves `TPUTS_SVR4` unset —
  identical behavior to before.
- `TPUTS_SVR4` is set only when the `char`-callback probe is the one that
  links, i.e. exactly the SVR4/Solaris case it targets. When set, `term_putchar`
  becomes `int term_putchar(char c)` matching the platform's `tputs`
  prototype; the body `fputc(c, ...)` is unaffected by the narrower parameter
  (the value is integer-promoted as before). No new path, no UB.
- `-pedantic-errors` is scoped to these compile/link feature probes only (not
  added to project-wide build flags), so it cannot introduce build regressions
  in the actual compilation of irssi.
- The CI YAML change is build-infra only and cannot affect the shipped product.

## Interactions with related changes
This builds directly on the Solaris work in #1557 (which introduced the
`solarisvm.yml` workflow and the curses.h namespacing) and is consistent with
the other portability siblings. The `putc_arg_t` macro is defined independently
and identically in both C files and is keyed off `TPUTS_SVR4`, which only this
change sets, so there is no ordering dependency or symbol overlap with the other
portability PRs. The meson block was later reformatted by the muon-fmt sibling
work but the logic is unchanged.
