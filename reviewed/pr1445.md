# #1445 — Prefer IPv6 by default when resolving

- Commit: 72df6652
- Verdict: SAFE

## What it changes
A one-line default flip in `servers_init()`: the boolean setting
`resolve_prefer_ipv6` is registered with a default of `TRUE` instead of
`FALSE`. This made irssi prefer the IPv6 address when a hostname resolved to
both IPv4 and IPv6 (in the then-current threaded gethostbyname resolver, the
setting selected which family was tried first). No logic or memory handling
is changed — only the default value of one setting.

## Files touched
- `src/core/servers.c`

## Release-safety findings
None — safe to release.

The diff itself is a trivial, well-bounded default change with no
correctness, memory, or injection implications.

Important context for the shipped release: this change is effectively a
no-op in the final 1.5.0 tree. A later sibling, #1580 ("use GIO resolver",
commit 51f2a4f7), removed the `server`/`resolve_prefer_ipv6` setting entirely
and renamed it to `irssiproxy_prefer_ipv6` (now only consumed by the
irssiproxy in `src/irc/proxy/listen.c` / `proxy.c`). At HEAD there is no
remaining reader of `resolve_prefer_ipv6`; the GIO resolver now walks the
resolver-returned address list in order (using
`G_RESOLVER_NAME_LOOKUP_FLAGS_DEFAULT`, narrowed only by an explicit
`-4`/`-6` family request), so IPv4-vs-IPv6 preference is governed by the
system/GIO ordering rather than this setting. The line modified by #1445 no
longer exists in the release, so it cannot break anything — but it also no
longer delivers the behavior its NEWS line and commit message describe.

## Interactions with related changes
Superseded by #1580 (51f2a4f7), which rewrote name resolution to use GIO and
deleted the `resolve_prefer_ipv6` setting this PR touched. Because the merge
ordering places #1580 after #1445, the value set here is overwritten/removed
and has no runtime effect in 1.5.0. Siblings #1605/#1607 are GResolver
follow-up fixes on the same resolver path; #1541/#1542 touch adjacent
resolver/error-handling code. No conflict or unsafe interaction — just
complete supersession.

## NEWS accuracy
The NEWS line "Prefer IPv6 by default when resolving (#1445)" accurately
describes the intent of this commit's diff in isolation. However, in the
shipped tree it is materially misleading: the setting it relied on was
removed by #1580 (whose own NEWS line at line 133 documents the
rename to `irssiproxy_prefer_ipv6`), and default IPv4/IPv6 ordering for
server connections is now decided by the GIO/system resolver, not by this
change. Listing #1445 as a user-facing "prefer IPv6 by default" feature
overstates what actually ships.
