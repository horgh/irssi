# #1394 — Speed up the Termux package CI by no longer building the perl package separately

- Commit: 5b0f7f78
- Verdict: SAFE

## What it changes
Only `.github/workflows/termuxpkg.yml`. It removes the separate `build-package.sh -i perl` step and switches the meson perl cross-file from a `[binaries] perl = [miniperl ...]` definition to a `[properties]` block (`perl_version`, `perl_ccopts`, `perl_ldopts`, `perl_archname`, `perl_installsitearch`, `perl_installvendorarch`, `perl_inc`). It also: drops the `rm -rf $TERMUX_PREFIX/lib/irssi/perl` reinstall hack; updates the package homepage/maintainer from the fork (ailin-nemui) to irssi.org/@irssi; adds a "prepare output folder" step (`install -m a+rwx -d output`); and runs the final build step under `sudo`.

## Files touched
- .github/workflows/termuxpkg.yml

## Release-safety findings
None — safe to release. This is a CI-only change with no effect on the shipped source, the runtime, or the ABI. The new `[properties]` keys match exactly the keys the build reads via `meson.get_cross_property(...)` in `meson.build` (lines 504, 526, 548, 636, 661), so the cross-file is consistent with the build's expectations. A CI workflow regression cannot break released binaries; at worst it would fail the Termux packaging job, which is observable in CI before release.

## Interactions with related changes
None.

## NEWS accuracy
Accurate. The headline change is removing the separate perl-package build step to speed up the Termux CI. The NEWS line does not mention the maintainer/homepage rebranding or the sudo/output-folder tweaks, but those are minor CI-internal adjustments and not material to the release.
