# #1543 — Add ipaddr and chosen_family fields to the Perl connection record

- Commit: fca3e83e
- Verdict: SAFE

## What it changes
Adds a new `char *ipaddr` field to `SERVER_CONNECT_REC` and exposes both
`ipaddr` and the (pre-existing) `chosen_family` field to Perl via
`perl_connect_fill_hash`. In `server_real_connect`, when an `IPADDR` is
available it now records `connrec->chosen_family = ip->family` and
`connrec->ipaddr = g_strdup(net_ip2host(...))`. The `chosen_family`
assignment was moved earlier in the function (now before the
`signal_emit("server connecting")` / `no_connect` early return), bundled
with the new `ipaddr` assignment. `server_connect_unref` gains a
`g_free_not_null(conn->ipaddr)`. The ABI version is bumped 54 -> 55, and
docs/perl.txt documents the two new Connect fields.

## Files touched
- src/common.h (ABI version 54 -> 55)
- src/core/server-connect-rec.h (new `char *ipaddr` field)
- src/core/servers.c (set chosen_family/ipaddr; free ipaddr in unref)
- src/perl/perl-common.c (expose chosen_family and ipaddr to Perl)
- docs/perl.txt

## Release-safety findings
None — safe to release.

Checked the items that could matter for release:
- Buffer sizing: `net_ip2host` requires a buffer of at least `MAX_IP_LEN`
  (= INET6_ADDRSTRLEN); the local `char ipaddr[MAX_IP_LEN]` matches this
  contract, so no overflow.
- Memory: `connrec->ipaddr` is `g_strdup`'d and the matching
  `g_free_not_null(conn->ipaddr)` is added to `server_connect_unref`. The
  connrec is freshly `g_new0`'d per connect/reconnect, so the field starts
  NULL; `server_connect_copy_skeleton` field-copies and intentionally does
  not copy `ipaddr` (the reconnect connrec keeps NULL), so there is no
  double-free or stale-pointer aliasing across reconnects.
- NULL safety in Perl: `conn->ipaddr` is NULL for unix-socket connections
  and before resolution; the `new_pv` macro maps NULL to an empty string,
  so `hv_store(... new_pv(conn->ipaddr) ...)` is safe.
- Moving the `chosen_family` assignment ahead of the `no_connect` early
  return only means the fields are populated even when `no_connect` is set;
  that connrec is still freed normally via unref, so no leak and no
  behavior regression.
- ABI bump is correct and required for the struct layout change.
