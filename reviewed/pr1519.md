# #1519 — Replace a deprecated OpenSSL 3 function

- Commit: 89f3e1ac
- Verdict: MINOR

## What it changes
In `set_server_temporary_key_info()` (TLS ephemeral key display), the EC
branch is split by OpenSSL version. On OpenSSL >= 3.0 it now uses the
non-deprecated `EVP_PKEY_get_group_name()` into a fixed `char cname[50]`
buffer instead of the deprecated `EVP_PKEY_get1_EC_KEY()` /
`EC_GROUP_get_curve_name()` / `OBJ_nid2sn()` chain (which is kept for
older OpenSSL and LibreSSL via the `#else` branch). The `switch` is
restructured to capture `EVP_PKEY_id()` into `keytype`, and the `default`
case now reports `OBJ_nid2ln(keytype)` instead of the literal string
`"Unknown"`. Adds `#include <openssl/objects.h>`. Pure display-path change;
no protocol or crypto behavior is affected.

## Files touched
- src/core/network-openssl.c

## Release-safety findings
- Unchecked return + uninitialized buffer on the OpenSSL 3 path:
  `char cname[50];` is declared uninitialized and
  `EVP_PKEY_get_group_name(ephemeral_key, cname, sizeof(cname), NULL)` is
  called without checking its `int` return value. The function only writes
  the buffer on success; on failure (no group name, or name longer than 49
  bytes) `cname` stays uninitialized and is then passed to
  `g_strdup_printf("ECDH: %s", cname)`, which reads uninitialized stack
  memory until a NUL (UB / possible stack over-read / garbage in the TLS
  info display). In practice an ephemeral ECDH key negotiated in a real TLS
  handshake always has a short, well-known group name (e.g. prime256v1,
  X25519), so the call effectively always succeeds and the buffer is
  populated; this is a latent defect, not an expected-path crash. Low
  release risk, but worth a one-line return-value/initialization guard.
- The `default`-case change from `"Unknown"` to `OBJ_nid2ln(keytype)` is a
  cosmetic string change only; `OBJ_nid2ln()` may return NULL, but
  `tls_rec_set_ephemeral_key_algorithm()` -> `g_strdup(NULL)` is safe (yields
  NULL), so no crash.
- Version guard is correct: `OPENSSL_VERSION_NUMBER >= 0x30000000L` scopes
  the OpenSSL-3-only API; LibreSSL (reports 0x20000000L) and pre-3.0 OpenSSL
  take the legacy `#else` branch where the deprecated functions still exist,
  so no build/portability regression. EC code remains under `OPENSSL_NO_EC`
  and `SSL_get_server_tmp_key` guards as before.

## NEWS accuracy
Accurate. The change replaces the deprecated OpenSSL EC-key accessor path
with `EVP_PKEY_get_group_name()` on OpenSSL 3. The NEWS line does not
mention the incidental `default`-case display change, but that is cosmetic
and not material.
