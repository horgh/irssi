## What it changes
Maintainer release-tooling only. Two files:

- `MANIFEST.in`: adds `recursive-include src/fe-fuzz *.c *.h *.txt meson.build`;
  adds `include irssi-icon.png`, `INSTALL`, `TODO`, `ChangeLog`, `.clang-format`;
  comments out the previous `prune subprojects/*/`, `prune Build`, `prune dist`
  directives; adds two `# ignore ...` comment lines (consumed by the script below).
- `utils/make-dist.sh`: adds a guard aborting if `pyproject.toml`/`setup.cfg`
  already exist; generates `ChangeLog` via `git log > ChangeLog`; writes a
  `pyproject.toml`; adds a `[check-manifest]` section to `setup.cfg` whose
  `ignore` list is populated from the `# ignore` lines in `MANIFEST.in` via a
  perl one-liner; runs `check-manifest` (only if the binary is present);
  quiets clone/sdist output. Also includes `pyproject.toml` in the
  post-build `tar --delete` cleanup.

These files build the source tarball; `make-dist.sh` is itself excluded from
the tarball (`exclude utils/make-dist.sh`) and is not run by end users.

## Release-safety findings
None — safe to release.

Verified the points that could plausibly matter:
- `src/fe-fuzz` is gated in meson by `if want_fuzzer` (`src/meson.build`), and
  `with-fuzzer` defaults to `no`. So normal end-user builds never enter that
  subdir; the new files change nothing for them. They only help the
  `-Dwith-fuzzer=yes` case, which previously failed from a tarball because the
  files were absent. Strict improvement.
- The tarball is produced from a fresh `git clone --no-local`, so only
  git-tracked files are present. Commenting out `prune subprojects/*/`,
  `prune Build`, `prune dist` is a no-op: the subproject sources, `Build/`,
  and `dist/` are all gitignored and absent from the clone. Only
  `subprojects/*.wrap` is tracked (and still explicitly included). The
  setuptools-created `dist/` is removed from the final tar by the existing
  `tar --delete` step.
- `ChangeLog` is referenced by `include ChangeLog` but is not tracked; it is
  generated at dist time by `git log > ChangeLog` before the manifest check.
- `check-manifest` is gated behind `command -v check-manifest`; if absent the
  script only warns and continues, so it cannot fail a release on a host
  lacking the tool. When present it validates the manifest — a gate, not a
  regression. Confirmed the perl extractor emits exactly the two intended
  ignore entries (`fuzz-support/fuzz.diff`, `utils/clang-format-xs/*`), which
  are tracked-but-intentionally-excluded files.
- No injection/security exposure: this is offline maintainer tooling; inputs
  are the project's own tracked files, not untrusted data.

Worst case of any defect here is a malformed tarball caught by the maintainer
during the release process, not a break shipped to users.
