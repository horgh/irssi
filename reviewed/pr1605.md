# #1605 — Add compatibility code for older GResolver versions

- Commit: 00466fe5
- Verdict: SAFE

## What it changes
Adds a fallback path in the async DNS resolver for GLib < 2.59, which lacks
`g_resolver_lookup_by_name_with_flags_async/finish` (the `_with_flags`
resolver API arrived in GLib 2.60). Specifically:

- `src/core/net-nonblock.c`: adds a `flags` member to
  `NET_GETHOSTBYNAME_CALLBACK_DATA` and stores the caller's flags into it.
  Behind `#if GLIB_CHECK_VERSION(2, 59, 0)` the modern `_with_flags`
  call is used; the `#else` branch calls the flag-less
  `g_resolver_lookup_by_name_async` and, in the finish callback, manually
  filters the returned `GList<GInetAddress>` to honor
  `IPV4_ONLY` / `IPV6_ONLY` (unref'ing and `g_list_delete_link`'ing the
  wrong-family entries). If filtering empties the list it synthesizes a
  `G_RESOLVER_ERROR_NOT_FOUND` error, mirroring modern GLib behavior.
- `src/core/network.h`: under the same version guard, provides a local
  `GResolverNameLookupFlags` enum (DEFAULT / IPV4_ONLY / IPV6_ONLY) for old
  GLib that does not define it.

This is the same fallback pattern already present for the synchronous path
in `net_gethostbyname()` (`src/core/network.c`).

## Release-safety findings
None — safe to release.

Verification notes:
- Build portability: the project's minimum GLib is `>=2.32` (meson.build),
  so the old-GLib branch is genuinely reachable and is in fact required —
  without it, building against GLib 2.32–2.58 would fail to compile the
  `_with_flags` call. All symbols used in the fallback
  (`g_resolver_lookup_by_name_async/finish`, `g_resolver_free_addresses`,
  `G_RESOLVER_ERROR_NOT_FOUND`, `g_inet_address_get_family`,
  `g_list_delete_link`) predate the 2.32 floor. No new portability risk.
- Memory management is correct: filtered-out addresses are `g_object_unref`'d
  and their links removed; the remaining list is later freed by
  `g_resolver_free_addresses()` in `resolved_ip_unref()`, so no double-free
  or leak. The empty-list case leaves `ailist == NULL` and sets `error`, and
  `g_resolver_free_addresses(NULL)` is safe.
- No NULL-deref in the consumer: when the fallback empties the list it sets
  `iprec->error`, so the `iprec->error->code` access in
  `server_connect_use_resolved()` (servers.c:324) is reached only with a
  non-NULL error. The continuation also handles `error == NULL &&
  ailist == NULL` separately before that path.
- The exact-equality flag checks (`== IPV4_ONLY` / `== IPV6_ONLY`) are safe:
  the sole caller (`servers.c`) passes exactly one of DEFAULT/IPV4_ONLY/
  IPV6_ONLY, never a combined bitmask.
- No injection surface: hostnames are passed to GLib's resolver; no string
  is built into a shell/SQL/format context. The synthesized error strings
  are fixed literals.
