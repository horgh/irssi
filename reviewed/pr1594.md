# #1594 — Fix hide_text_style and hide_colors to mitigate color bleed on the reset control code

- Commit: 6c72dc14
- Verdict: SAFE

## What it changes
In `format_send_as_gui_flags()` (`src/fe-common/core/formats.c`), the handling of
`case 15` — the IRC reset/plain control code `\x0f` (Ctrl-O), called out as the
"reset control code" — is now gated behind the `hide_text_style` and `hide_colors`
settings.

Before, the reset unconditionally did:
```
fgcolor = theme->default_color;
bgcolor = -1;
flags &= GUI_PRINT_FLAG_INDENT|GUI_PRINT_FLAG_MONOSPACE;
```
After:
```
if (!hide_text_style) {
    if (!hide_colors) {
        fgcolor = theme->default_color;
        bgcolor = -1;
    }
    flags &= GUI_PRINT_FLAG_INDENT | GUI_PRINT_FLAG_MONOSPACE;
}
```
So when style hiding is on, the reset no longer clears the style flags; when color
hiding is on, the reset no longer forces fg/bg back to theme defaults. This makes
`\x0f` consistent with the rest of the switch, where every other style/color control
code already checks these flags (cases 2, 3, 6, 17, 22, 29, 31, 27).

## Files touched

## Release-safety findings
None — safe to release.

- Default behavior is unchanged. Both `hide_text_style` and `hide_colors` default to
  FALSE (`fe-common-core.c:161-162`), so the modified branch produces byte-identical
  output to the old code in the default configuration. The new behavior is only
  reachable when a user has explicitly enabled hiding.
- The settings derivation `hide_colors = hide_text_style || settings_get_bool("hide_colors")`
  (line 1691) means `hide_text_style` implies `hide_colors`. The nested condition
  handles all four resulting states correctly: with `hide_text_style` set, the whole
  block is skipped; with only `hide_colors` set, colors are preserved but style flags
  are still cleared.
- No memory/UB risk: the change only gates assignments behind booleans. It adds no
  pointer arithmetic, no dereferences, and does not alter how `ptr`/`str` advance, so
  no new out-of-bounds exposure. `theme->default_color` is referenced exactly as
  before.
- No security/injection surface: this is display-side rendering of control codes that
  have already been parsed; the change makes output strictly less aggressive (it
  suppresses, rather than adds, state changes).

## Interactions with related changes
None. The change is isolated to one switch case in master and does not touch shared
state used by sibling 1.5.0 changes.

## NEWS accuracy
Accurate. The NEWS line ("Fix hide_text_style and hide_colors to mitigate color bleed
on the reset control code") precisely matches the diff: it targets the IRC reset
control code (`\x0f`, `case 15`) and gates it on both settings. Note that irssi's own
`%n` directive (`FORMAT_STYLE_DEFAULTS`, lines 1489-1493) performs the same reset and
is intentionally left unchanged — that is a user-authored format directive rather than
the network-sourced reset code the NEWS line describes, so this is consistent, not a
scope gap.
