# #1430 — Add list-of-lists support and clearer error messages to the config parser, and fix a time zone assertion by parsing ISO 8601 times as UTC

- Commit: 8eca391b
- Verdict: SAFE

## What it changes
Four logically distinct changes merged together:

1. Config parser (`src/lib-config/parse.c`, `iconfig.h`): adds a `list_of_lists : 1`
   bitfield to `CONFIG_REC` and adds two `g_scanner_error()` calls ("Missing key",
   "List of lists not allowed") on the existing error paths in `config_parse_symbol`.
   The `(` branch now only errors when `key == NULL && !rec->list_of_lists`.

2. Time-zone fix (`fe-log.c`, `textbuffer-formats.c`): both call sites of
   `g_date_time_new_from_iso8601(val, NULL)` now pass a UTC `GTimeZone` (`utc`)
   instead of `NULL`. A module-global `GTimeZone *utc` is created in each module's
   `_init` via `g_time_zone_new_utc()` and unref'd in `_deinit`.

3. Internal/bundled glib bump (`meson.build`, `subprojects/glib.wrap`): the optional
   `-Dinstall-glib=yes` fallback glib is moved from 2.58.3 to 2.74.3, switches the
   subproject options to meson `feature` style (`-Dlibmount=disabled`,
   `-Dselinux=disabled`, `-Dforce_fallback_for=pcre2`), and explicitly builds and
   links `libpcre2-8.a` (glib 2.73+ requires PCRE2 instead of internal PCRE1). The
   wrap hash is updated to match 2.74.3.

4. ABI bump (`src/common.h`): `IRSSI_ABI_VERSION` 50 → 51.

## Release-safety findings
None — safe to release.

Notes considered and cleared:

- Time-zone fix is correct and narrowly scoped. The "time" value parsed here comes
  from the IRCv3 `time` message tag (see `src/irc/core/irc.c` `irc_server_event_tags`),
  which per spec is UTC with a `Z` suffix. For offset-bearing strings the `default_tz`
  argument is ignored by glib, so behavior is unchanged for well-formed tags. The only
  behavior change is for malformed/offset-less inputs, which now resolve as UTC instead
  of local time — the more correct interpretation, and it avoids the glib assertion the
  fix targets. The compat fallback `g_date_time_new_from_iso8601` (src/core/misc.c, used
  on glib < 2.56) already parses as UTC and ignores `default_tz`, so it stays consistent.

- `utc` GTimeZone globals: `_init`/`_deinit` are each called exactly once
  (fe-common-core.c and irssi.c). `g_time_zone_new_utc()` ref + `g_time_zone_unref()`
  are balanced; no leak, no double-free, no use-after-free.

- ABI bump is appropriate and safe: `CONFIG_REC` (in the installed header `iconfig.h`)
  changed layout, and the version is checked at module load (`modules-load.c`), so
  stale modules are cleanly rejected rather than crashing.

- The `list_of_lists` field is allocated via `g_new0` (defaults to 0) and is never set
  to 1 anywhere in the tree. The parser change is therefore behavior-preserving for
  existing config files: the `(`-without-key and `{`-without-key cases still return
  `G_TOKEN_ERROR` exactly as before — they just additionally record an error message.
  No parsing regression for existing user configs.

- Internal-glib meson changes are coherent with glib 2.74's PCRE1→PCRE2 transition and
  the wrap hash matches. This path is opt-in (system glib, still `>=2.32`, is the
  default and unaffected).

## Interactions with related changes
None. The parser, time-zone, and build changes are independent. The ABI bump is the
expected accompaniment to the `CONFIG_REC` struct change and does not conflict with
other 1.5.0 changes.

## NEWS accuracy
Largely accurate, with one scope caveat:

- "clearer error messages to the config parser" and "fix a time zone assertion by
  parsing ISO 8601 times as UTC" are accurate.
- "Add list-of-lists support" overstates what ships: the `list_of_lists` gate is added
  but no code path ever enables it (the field is always 0), so the feature is plumbed
  but not actually exposed/usable to end users in this release. Not a safety issue, just
  a description that promises slightly more than is reachable.
- NEWS does not mention the bundled-glib bump (2.58→2.74) or the ABI bump; these are
  implementation details supporting the time-zone fix and don't affect default
  (system-glib) builds, so the omission is reasonable.
