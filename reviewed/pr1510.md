# #1510 — Restore the locale if Perl breaks it

- Commit: 504fd7bc
- Verdict: SAFE

## What it changes
Replaces the previous Perl-version-string-based locale workaround (in
`irssi-core.pl`, gated on `$] >= 5.037005 && $] <= 5.038000`) with a runtime
detection in `perl-core.c`. It probes libc `wcwidth(160)` (U+00A0 NBSP) both
before and after `perl_construct()`; if the result changes, Perl clobbered the
C locale (Perl5 bug #21366, seen in 5.38.0). In that case it emits a
`g_warning` and runs a small Perl snippet that calls
`POSIX::setlocale(LC_ALL, "")` to restore the locale from the environment.
The detection is purely behavioral instead of matching specific version
numbers, so it no longer depends on the exact broken Perl release.

## Files touched
- src/perl/perl-core.c
- src/perl/irssi-core.pl (removes the old version-gated block)

## Release-safety findings
None — safe to release.

Notes considered:

- The raw feature commit (a0caf5e5, the second parent of merge 504fd7bc) added
  `wcwidth(160)` calls but did NOT add `#include <wchar.h>` or define
  `_GNU_SOURCE`, which is an implicit-declaration / missing-prototype bug.
  However, the release ships master, and two follow-up commits that are both
  ancestors of master fix this completely:
    - 9fd6df2a "add missing include for wcwidth thread test" adds
      `#define _GNU_SOURCE` + `#include <wchar.h>` (NEWS line 105).
    - 838f8d17 "fix _GNU_SOURCE redefined warning due to perl ccflags"
      guards the define with `#ifndef _GNU_SOURCE` to avoid a redefinition
      warning when Perl's ccflags already define it (#1572, NEWS line 109).
  In the shipped master tree the include is present and ordered before any
  system header, so there is no implicit declaration and no portability/build
  regression. The merge 504fd7bc in isolation was incomplete, but it does not
  ship in isolation.

- Behavior change is conditional and a restoration, not a new default: the
  `setlocale(LC_ALL, "")` only runs when runtime detection shows Perl actually
  corrupted the locale. On unaffected Perl builds, `broken_perl` is false and
  nothing changes for the user. When it does fire it restores the
  environment-defined locale that irssi already used before Perl init, so it
  does not override a user who is deliberately running in the C locale beyond
  what Perl had already broken.

- The libc `wcwidth(3)` used here is distinct from irssi's bundled `i_wcwidth`
  wrapper; using libc's is correct since the point is to observe the libc
  locale state that Perl mutated. No symbol collision.

- `g_warning` could abort under `G_DEBUG=fatal-warnings`, but that is a
  non-default debug setting, not a release concern.
