# #1560 — Fix a build issue by adding a missing wchar.h include in the Perl core

- Commit: 4ec9d109
- Verdict: SAFE

## What it changes
Adds three lines at the top of `src/perl/perl-core.c`:

```c
#define _GNU_SOURCE
#include <wchar.h>
```

The file already calls `wcwidth(160)` in `perl_scripts_init()` (introduced
earlier in a0caf5e5, "restore locale if perl breaks it") as part of detecting
a broken-Perl locale workaround, but never included `<wchar.h>`. `wcwidth()`
is an XSI/GNU extension, so glibc only declares it from `<wchar.h>` when an
appropriate feature-test macro is set; defining `_GNU_SOURCE` before the
include exposes it. This corrects an implicit-declaration build issue.

## Files touched
- `src/perl/perl-core.c`

## Release-safety findings
None — safe to release.

- The `#define _GNU_SOURCE` / `#include <wchar.h>` are placed before any
  other header, which is the correct location for a feature-test macro to
  take effect. No behavior change: `wcwidth` was already linked/used; this
  only adds the missing prototype so the compiler sees the correct
  declaration. No runtime, ABI, or default-behavior change.

## Interactions with related changes
The bare `#define _GNU_SOURCE` can trigger a "_GNU_SOURCE redefined" warning
on toolchains where Perl's ccflags already define it. That is addressed by
sibling PR #1572 (commit 838f8d17, "fix _GNU_SOURCE redefined warning due to
perl ccflags"), which wraps the define in `#ifndef _GNU_SOURCE` / `#endif`.
Both 4ec9d109 and 838f8d17 are on master and will ship in 1.5.0, so the
final released state has the guarded form and the redefinition warning is
resolved. No ordering hazard for the release. No overlap or conflict with the
other listed portability siblings (pr1557, pr1540, pr1558, pr1576, pr1578).
