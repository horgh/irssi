   setuptools (`'setuptools<66'`).

   registrations with `hasattr`) to make old setuptools import under Python 3.12.

   stripped from the release tarball. Old code passed four hardcoded member
   names to `tar --delete` (incl. the `$name.egg-info` directory). New code does
   `tar tf <tar> | grep -F <newline-separated list>` and passes the matched
   member names to `tar --delete`.

Only `make-dist.sh` ships in / affects the actual release artifact. The two
workflow files are CI-only (not in MANIFEST.in, not in the tarball); they only
matter insofar as CI is what validates the release.

## Release-safety findings

`utils/make-dist.sh` — the `tar --delete` rewrite is a regression that can abort
the script that builds the release tarball.

- The script runs under `#!/bin/sh` with `set -e` (line 4). The new deletion is:

  ```sh
  tar --delete --file "dist/$name-$version.tar" \
      $(tar tf "dist/$name-$version.tar" | grep -F \
        "$name-$version/setup.cfg
  $name-$version/pyproject.toml
  $name-$version/$name.egg-info
  $name-$version/PKG-INFO")
  ```

- A standard setuptools sdist tar (built via distutils `make_tarball`, which
  uses Python's recursive `tarfile.add`) contains a *directory* member
  `$name-$version/$name.egg-info/` that appears BEFORE its file children
  (`PKG-INFO`, `SOURCES.txt`, `dependency_links.txt`, ...).

- `grep -F` is a substring match, so the enumerated argument list includes the
  `.egg-info/` directory member AND each of its children (and the top-level
  `PKG-INFO` matches the `.egg-info/PKG-INFO` line too). The arguments are in
  archive order, so the directory comes first.

- GNU `tar --delete` of a directory member cascade-removes the directory and all
  its children in one step. The subsequent explicit child members are then "Not
  found in archive", so tar prints errors and `Exiting with failure status`
  (exit code 2). Under `set -e` in `/bin/sh`/dash this aborts `make-dist.sh`,
  failing the `dist` CI job and producing no tarball.

  Reproduced deterministically: an archive with `.egg-info/` dir entries makes
  the new code exit 2 and abort; the old hardcoded version (which only deletes
  the directory, never listing children) exits 0 on the same archive.

- The new code only succeeds if the sdist tar contains NO directory entries
  (a pure file-list archive); in that case both old and new behave identically.

Because I could not install setuptools in this sandbox to dump a real sdist's
member layout, I cannot 100% confirm the production archive contains the
`.egg-info/` directory entry — but the standard tooling produces it, and the
failure under that layout is deterministic. This should be verified before
release: run `./utils/make-dist.sh` (or inspect a recent `dist` CI run) and
confirm it actually produces `irssi-*.tar.gz` and exits 0. If the dist job has
been passing, the production sdist evidently lacks dir entries and this is a
latent fragility rather than an active break; if it has not been exercised since
this change, the release-tarball step is broken.

No injection/security concerns: inputs (`$name`, `$version`) come from
`meson.build`, not untrusted data, and `grep -F` treats the list literally.
