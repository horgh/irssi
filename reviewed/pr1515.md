# #1515 — Add a missing include to fix the fuzz build under clang-18

- Commit: aebc0667
- Verdict: SAFE

## What it changes
Adds a single `#include <irssi/src/core/network-openssl.h>` to
`src/fe-fuzz/server.c`. That header declares `gboolean irssi_ssl_init(void)`,
which the file already calls in `LLVMFuzzerInitialize()` (line 156). Without the
include the call relied on an implicit/missing declaration, which clang-18
rejects (implicit function declarations are now an error by default), breaking
the fuzz build. The include supplies the prototype.

## Files touched
- `src/fe-fuzz/server.c` (1 insertion, +1 line)

## Release-safety findings
None — safe to release.

- The change is confined to the fuzzing harness. `src/fe-fuzz` is only built
  when the `with-fuzzer` meson option is `yes` (`src/meson.build` line 22-24
  guards `subdir('fe-fuzz')` on `want_fuzzer`). It is never part of a normal
  release build, so end users and packagers are unaffected.
- The included header exists, has a proper include guard
  (`IRSSI_CORE_NETWORK_OPENSSL_H`), and declares exactly the symbol used.
- `network-openssl.c` is unconditionally compiled into `libcore_a`
  (`src/core/meson.build` line 34, no SSL/TLS conditional), and the server-fuzz
  target links `libcore_a`, so `irssi_ssl_init` resolves at link time. The
  header is also unconditionally installed (`src/core/meson.build` line 105).
- No behavioral change to any code: only a declaration is brought into scope;
  no logic, signatures, or call sites are modified. No memory, UB, or injection
  surface is touched.

## Interactions with related changes
None. The diff is an additive include in an isolated, build-gated harness file.
