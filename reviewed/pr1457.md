# #1457 — Properly format listmodes and their timestamps, add human-readable relative times, and support ircd-hybrid quiet lists

- Commit: 83ebc0a0
- Verdict: MINOR

## What it changes
Reworks how ban/ban-exception/invite list timestamps are displayed and adds
quiet-list support.

- New `time_ago()` helper formats an elapsed `time_t` into a human-readable
  relative string ("3w 2d 5h", etc.) using a `static char[128]` buffer.
- `event_ban_list` (367), `event_eban_list` (348) and `event_invite_list`
  (346) now compute both an absolute date string via `my_asctime()` and a
  relative "ago" string via `time_ago()`, instead of passing a raw `long`
  seconds count. `atol` is replaced by `atoll`.
- Adds `event_quiet_list` (numeric 728) and `event_hybrid_quiet_list`
  (numeric 344, ircd-hybrid) plus a shared `do_quiet_list()`. Numeric 344 was
  previously the generic "reop list" handler; it is now re-purposed for the
  hybrid quiet list, falling back to the old `event_target_received` path when
  the timestamp field is empty ("probably not a quiet list"). 728 was
  previously routed to the generic `event_target_received`.
- New formats `quietlist` / `quietlist_long`; the four `*_long` formats are
  rewritten to take the date + relative-time strings (all `FORMAT_STRING`),
  replacing the old "$N secs ago" integer form.
- Bumps `IRSSI_ABI_VERSION` 51 -> 52 (correct: format enum values shift).

## Release-safety findings
- Memory leak (MINOR) in `event_hybrid_quiet_list`
  (src/fe-common/irc/fe-events-numeric.c:729). On the early-return path
  (`*tims == '\0'`, i.e. the common case where 344 is actually a reop list and
  not a quiet list), the function returns after calling
  `event_target_received` without `g_free(params)`. `event_get_params` returns
  a `g_strdup`'d buffer that the caller must free, so every non-quiet 344
  numeric leaks one params allocation. Server-triggered and unbounded over a
  long session, but small and not amplifiable into a crash — not a blocker.

- Display bug (MINOR, cosmetic) in `ebanlist_long`
  (src/fe-common/irc/module-formats.c:88). The arg order passed by
  `event_eban_list` is `..., timestr, ago` ($3=timestr, $4=ago), but the
  format text is `... on $4 ($3 ago)`, so it renders as
  "on <relative-time> (<absolute-date> ago)" — the date and relative time are
  swapped. The other three `*_long` formats (banlist/quietlist/invitelist) map
  their slots correctly. Wrong output only; no memory/UB impact.

The following were checked and are NOT problems:
- No buffer overflow in `time_ago`: output into the 128-byte static buffer is
  bounded for all inputs. Server-supplied/garbage/future timestamps yield a
  negative `time(NULL)-seconds`; the subsequent unsigned division/modulo is
  well-defined (no UB) and only produces odd-looking values, not a crash.
- The `static` return buffer of `time_ago` is safe here: each call site makes
  exactly one `time_ago` call and one `printformat` before any reuse, and
  irssi is single-threaded.
- Vararg count/type match: `format_read_arglist` reads exactly
  `format->params` args with per-arg types. All four `*_long` calls pass the
  declared count with matching types (banlist_long's first param is the int
  index; all timestamp/relative args are `char *`). Short formats receive
  extra trailing varargs, which are correctly ignored.
- `my_asctime` returns a heap string; the matching `g_free(timestr)` is
  correct, and the static-buffer `ago` is (correctly) not freed.
- Enum order in module-formats.h matches the array order in module-formats.c;
  728/344/345 signal add/remove pairs are balanced; reop-list display (344
  with empty timestamp) is preserved via the fallback. No NULL-deref: missing
  trailing params resolve to "" not NULL.
