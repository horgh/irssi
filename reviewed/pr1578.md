# #1578 — Make compilation work on Cygwin by using shared_library instead of shared_module

- Commit: d5be7d77
- Verdict: SAFE

## What it changes
A build-system (meson) change plus one tiny C change to make irssi compile and
run on Cygwin:

- `src/core/modules-load.c`: `module_get_name()` now strips a leading `cyg`
  prefix in addition to `lib`, so Cygwin-named modules (`cygfoo.dll`/`.so`)
  resolve to the expected module name.
- `meson.build`: adds `need_dl_cross_link_main` / `dl_cross_irssi_main`
  plumbing; for `host_machine.system() == 'cygwin'` both `need_dl_cross_link`
  and `need_dl_cross_link_main` are set true (mirroring the existing Android
  cross-link behavior).
- `src/fe-none/meson.build`, `src/fe-text/meson.build`: capture the built
  executable into a variable, add `implib : true`, and on Cygwin populate
  `dl_cross_irssi_main` with the main executable so modules can link against
  the executable's import library.
- `src/meson.build`: reorders subdir processing so the executables
  (`fe-none`/`fe-text`) and `fe-common/core` are built before the loadable
  modules that now need `dl_cross_irssi_main`. The set of subdirs processed is
  unchanged; `fe-common/meson.build` is emptied and its `core`/`irc` subdirs
  are driven from `src/meson.build` instead.
- All loadable modules (irc core/dcc/flood/notifylist/proxy, fe-common irc
  variants, otr, all perl modules) are converted from `shared_module(...)` to
  `shared_library(...)` with `override_options : ['b_lundef=false']` added, and
  `dl_cross_irssi_main` (and in some cases `dl_cross_irc_core`) appended to
  their `link_with`.

## Release-safety findings
None — safe to release.

Detail behind the verdict (these were checked and are NOT problems):

- Module filename change on Unix: `shared_module()` defaults to an empty
  `name_prefix` (e.g. `irc_core.so`), whereas `shared_library()` defaults to a
  `lib` prefix on Unix (e.g. `libirc_core.so`). This changes the *installed*
  module filenames on Linux/BSD/Solaris. It does NOT break loading: irssi
  resolves modules by stripping the `lib` prefix in `module_get_name()` and
  delegates path construction to glib's `g_module_open`/`g_module_build_path`,
  which expects the `lib` prefix on Unix. The perl modules already pin
  `name_prefix : ''` (required by Perl's loader) so those filenames are
  unchanged. This is validated by CI: the Ubuntu (`check.yml`), Solaris
  (`solarisvm.yml`) and Void (`voiddocker.yml`) jobs all `ninja install` and
  then run a launch test that executes `load irc/dcc/flood/notifylist/perl/
  otr/proxy`, exercising the exact name-resolution path on the new filenames.
  Since this merged to master (the 1.5.0 branch), those passed.

- `b_lundef=false` added everywhere: `shared_library` defaults to
  `b_lundef=true` (forbid undefined symbols at link), which would break these
  modules because they reference symbols resolved at runtime from the main
  binary. `shared_module` already permitted undefined symbols, so adding
  `b_lundef=false` restores the prior, correct behavior and does not hide new
  runtime-resolution problems.

- `implib : true` on the executables: meson only emits an import library on
  PE targets (Windows/Cygwin); it is a no-op on ELF/Mach-O platforms, so it is
  harmless to the primary release platforms.

- subdir reordering in `src/meson.build`: the new ordering is required so
  `dl_cross_irssi_main` (set in fe-none/fe-text) exists before the modules
  link. fe-none/fe-text link only against `libconfig_a`/`libcore_a`/
  `libfe_common_core_a`, all produced in earlier subdirs, so the reorder
  introduces no missing-dependency ordering bug. On all non-cross-link
  platforms `dl_cross_irssi_main` stays `[]`, so the appended `link_with`
  entries are empty and the reorder is behavior-neutral.

## Interactions with related changes
This is part of the "portability" group (pr1557, pr1540, pr1558, pr1560,
pr1572, pr1576). The change reuses and extends the existing Android
cross-link machinery (`need_dl_cross_link`, `dl_cross_*`), so it overlaps with
any sibling that touches those meson variables or the same `meson.build`
files; no conflict is visible in the merged tree. The siblings were not
reviewed in depth per instructions.

One non-default edge case worth noting (not a blocker): on Cygwin only, if a
build enables BOTH `with-bot=yes` AND text UI, `dl_cross_irssi_main` is first
set to the `botti` executable then overwritten by the `irssi` executable
(last writer wins), so modules link only against `irssi`'s import library.
This affects neither the default configuration (bot off, text UI on, so only
`irssi` is set) nor any non-Cygwin platform (where the variable stays empty).

## NEWS accuracy
Accurate. The NEWS line ("Make compilation work on Cygwin by using
shared_library instead of shared_module") correctly captures the headline
mechanism. It does not mention that the `shared_module` -> `shared_library`
conversion is applied globally (all platforms) rather than only on Cygwin, but
that is an implementation detail and not a material scope misstatement for a
changelog entry.
