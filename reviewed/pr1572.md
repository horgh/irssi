# #1572 — Fix a _GNU_SOURCE redefined warning caused by Perl ccflags

- Commit: aa285d45
- Verdict: SAFE

## What it changes
Wraps the unconditional `#define _GNU_SOURCE` at the top of
`src/perl/perl-core.c` in an `#ifndef _GNU_SOURCE` / `#endif` guard. Perl's
`ExtUtils::Embed` ccopts are pulled into the compile command for this object
(meson.build lines 504-521 forward any `-D...` flag into `perl_cflags`, which
becomes `perl_dep`'s `compile_args`). Those ccflags commonly include
`-D_GNU_SOURCE`, so the in-source unconditional define produced a
"_GNU_SOURCE redefined" compiler warning. The guard suppresses the
redefinition when the macro is already defined on the command line.

## Files touched
- src/perl/perl-core.c (2 lines added)

## Release-safety findings
None — safe to release.

The `#define _GNU_SOURCE` still appears before the first `#include`
(`<wchar.h>` at line 24, then `module.h`), so the feature-test macro is still
in effect for the wide-char declarations (e.g. `wcwidth`) that the file
relies on. glibc only checks whether `_GNU_SOURCE` is defined, not its value,
so suppressing the redefine when Perl already passes `-D_GNU_SOURCE` causes no
behavioral difference. Purely a compile-time warning fix; no runtime, ABI, or
security impact, and no injection surface.

## Interactions with related changes
None functional. Other portability files (`src/otr/otr-module.c`,
`src/otr/key.c`, `src/otr/otr.c`, `src/core/wcwidth-wrapper.c`) still define
`_GNU_SOURCE` unconditionally, but those are not compiled with Perl ccflags so
they do not hit this redefinition and need no matching change. No ordering
