# #1607 — Fix several issues with the GIO resolver

- Commit: 80b8875f
- Verdict: SAFE

## What it changes
Merge of "GResolver fixes" touching the name-resolution path. Four distinct fixes:

1. **Capsicum path relocation + signature fix** (`network.c`): The `HAVE_CAPSICUM`
   short-circuit was moved out of `net_gethostbyname()` (which returns
   `RESOLVED_IP_REC *`) into `net_gethostbyname_first_ips()` (which returns `int`).
   The call was also corrected from `capsicum_net_gethostbyname(addr, flags)` to
   `capsicum_net_gethostbyname(addr, ip4, ip6)`, matching the real prototype
   `int capsicum_net_gethostbyname(const char *, IPADDR *, IPADDR *)`. Previously
   an `int` was being returned as a pointer and the arguments did not match the
   prototype.

2. **Old-GLib compatibility for the sync resolver** (`network.c`): For GLib
   < 2.59 (no `g_resolver_lookup_by_name_with_flags`), it now falls back to
   `g_resolver_lookup_by_name` and manually filters the result list by family for
   IPV4_ONLY/IPV6_ONLY, synthesizing a `G_RESOLVER_ERROR_NOT_FOUND` if the list
   becomes empty. This mirrors the already-present async compat code in
   `net-nonblock.c`.

3. **Loop fix** (`network.c`): the iteration in `net_gethostbyname_first_ips`
   changed from `for (curr = ...; curr->next; ...)` to `for (curr = ...; curr;
   ...)`. The old condition skipped the last list element and dereferenced a NULL
   `curr` when the list was empty.

4. **Two memory leaks fixed** (`servers.c`): `server_connect_use_resolved` now
   `g_free(ip)`s the locally allocated `IPADDR`; `server_connect_callback_resolved`
   now `g_object_unref`s `server->connect_cancellable` before nulling it instead
   of just dropping the reference.

`servers-setup.c` change is whitespace/brace-only (no behavior change).

## Release-safety findings
None — safe to release.

Notes from verification (all benign):
- `g_free(ip)` is safe: `server_real_connect` only reads `ip` (copies into
  `connrec->ipaddr`, passes to `net_connect_ip`); it does not retain the pointer.
  In the error branch `ip` is NULL, so `g_free` is a no-op.
- The `g_object_unref(connect_cancellable)` is correct and not a double-free:
  `net_gethostbyname_nonblock` returns a fresh `g_cancellable_new()` reference
  owned by the server; by the time the `_finish` callback fires the async ref is
  already gone, so this is the last reference. The callback nulls the field after
  unref, so other cleanup paths (`servers.c:54`, `servers-reconnect.c:123`) see
  NULL and won't unref again. Matches the established pattern.
- The compat-code resolver flag enum (`GResolverNameLookupFlags`) is locally
  defined in `network.h` for GLib < 2.59, so the new branch compiles on old GLib.
- The capsicum module is FreeBSD-only and opt-in (`--with-capsicum`). The
  separate signature mismatch at `capsicum.c:282`
  (`net_gethostbyname(addr, &ip4, &ip6)` calling an undeclared symbol) is
  pre-existing and untouched by this PR; this PR only improves the capsicum
  caller in `net_gethostbyname_first_ips`. No regression for default builds.
- The potential NULL-deref of `iprec->error` in the `ip == NULL` branch of
  `server_connect_use_resolved` is pre-existing (the empty-list-no-error case is
  already short-circuited in `server_connect_callback_resolved`) and is not
  affected by the added `g_free(ip)`.

synchronous `net_gethostbyname` (network.c), so the two are consistent. The
