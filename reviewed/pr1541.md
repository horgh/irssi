# #1541 — Replace obsolescent inet_addr/inet_aton with inet_pton

- Commit: a1c8edfa
- Verdict: SAFE

## What it changes
In `net_host2ip()` (src/core/network.c), the IPv4 parsing branch is rewritten.
Previously it used `inet_aton()` (under `#ifdef HAVE_INET_ATON`) or fell back to
`inet_addr()` + `INADDR_NONE` check + `memcpy(&ip->ip, &addr, 4)`. Now it uses a
single `inet_pton(AF_INET, host, &ip->ip)` call, matching the IPv6 branch that
already used `inet_pton`. The local `unsigned long addr;` temporary is removed.
Net diff is 1 insertion / 11 deletions in one file.

## Files touched
- src/core/network.c

## Release-safety findings
None — safe to release.

Details considered:
- Memory/buffer safety: `inet_pton(AF_INET, ...)` writes exactly 4 bytes (a
  `struct in_addr`) into `&ip->ip`, which is a `struct in6_addr` (16 bytes), so
  there is no overflow. This matches the old `memcpy(..., 4)` / `inet_aton`
  behavior: only the first 4 bytes are written, bytes 4–15 are left as-is. The
  consuming code reads only 4 bytes for AF_INET (e.g. `memcpy(&so->sin.sin_addr,
  &ip->ip, 4)`), so the untouched tail bytes are irrelevant. No behavioral
  change here.
- Return-value handling: `inet_pton` returns 1 (ok), 0 (malformed), or -1
  (unsupported family, sets EAFNOSUPPORT). The code checks only `== 0` → returns
  -1. The -1 case cannot occur because AF_INET is always a supported family, so
  treating a -1 result as success is not reachable in practice. Equivalent to
  the old `inet_aton == 0` / `INADDR_NONE` failure checks.
- Parsing strictness: `inet_pton` accepts only strict dotted-quad
  "a.b.c.d". The old `inet_aton`/`inet_addr` accepted loose/abbreviated forms
  (e.g. "127.1", octal "0177.0.0.1", a bare 32-bit number). Such inputs now
  fail to parse. This only affects the `dcc_own_ip` setting and DCC address
  parsing, where canonical dotted-quad is the normal form; rejecting the loose
  forms is more correct and is not a crash/security concern. This is a minor,
  acceptable behavior tightening, not a release risk.
- Build/portability: meson-only build; `HAVE_INET_ATON` is never defined by
  meson (the removed `inet_aton` branch referenced `&ip->ip.s_addr` on a
  `struct in6_addr`, which has no `s_addr` member and would not have compiled —
  confirming that branch was dead). `inet_pton` was already used in the same
  function for the IPv6 branch, so availability is established. No leftover
  `inet_aton`/`HAVE_INET_ATON`/`INADDR_NONE`-dependent C code remains (the meson
  `inet_addr` link probe and `INADDR_NONE` fallback define are harmless and
  untouched). No injection surface (no shell/format-string involvement).

None. This is a self-contained 1-file change. Sibling resolver changes
