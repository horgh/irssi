# #1575 — Document the existing -priority option in the HILIGHT syntax help

- Commit: 995e77c3
- Verdict: SAFE

## What it changes
A single-line edit to a C comment. The `/* SYNTAX: HILIGHT ... */` block above
`cmd_hilight()` in `src/fe-common/core/hilight-text.c` gains `[-priority <number>]`
on the line listing `-color`/`-actcolor`/`-level`. No code, parsing, or logic is
touched.

The `-priority` option itself is not new: it is already registered in
`command_set_options("hilight", "... -priority ...")` (line 805), parsed into
`rec->priority` (lines 651/677), persisted/round-tripped to config (lines 76,
543, 587-588), and used in match selection (lines 276-282, 314-315). This commit
only adds it to the SYNTAX summary comment.

## Files touched
- src/fe-common/core/hilight-text.c (1 line, comment only)

## Release-safety findings
None — safe to release. This is a comment-only change with zero runtime effect.
The SYNTAX comment is consumed solely by the build-time helper `utils/syntax.pl`,
which substitutes `@SYNTAX:hilight@` in `docs/help/in/hilight.in` to regenerate
the help file. No injection, ABI, behavior, default, or build/portability concern.

## Interactions with related changes
None. Independent of other 1.5.0 changes.

## NEWS accuracy
Accurate. The NEWS line (#1575) says it documents the existing `-priority` option
in the HILIGHT syntax help, which is exactly what the diff does — the option
already existed and is even already described in the body of
`docs/help/in/hilight.in` (line 20: "-priority: The priority to use when multiple
highlights match"); only the syntax summary line was missing it.
