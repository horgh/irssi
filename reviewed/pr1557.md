# #1557 — Fix building on Solaris by namespacing TERM_REC functions that conflict with curses.h, and add a Solaris CI build

- Commit: 5a9a9aba
- Verdict: SAFE

## What it changes
- Renames all function-pointer members of `struct _TERM_REC` (the internal terminfo terminal abstraction) from generic names (`move`, `scroll`, `clear`, `clrtoeol`, `repeat`, `set_fg`, `set_bg`, `set_normal`, `set_blink`, `set_bold`, `set_reverse`, `set_uline`, `set_standout`, `set_italic`, `set_cursor_visible`, `move_relative`, `beep`) to `tr_`-prefixed names. Several of the old names (`move`, `clear`, `scroll`, etc.) collide with macros/identifiers exposed by `curses.h`, which Solaris requires when including `term.h`.
- Adds a meson configure-time check: when `term.h` is present but a bare `#include <term.h>` won't link `tputs`, it tries `curses.h` + `term.h`; if that links, it defines `NEED_CURSES_H`. (The current tree has since been extended by sibling PRs to also handle `TPUTS_SVR4` and `-pedantic-errors`, but the as-landed commit only added the `NEED_CURSES_H` path.)
- In `terminfo-core.c` and `term-terminfo.c`, conditionally `#include <curses.h>` before `<term.h>` when `NEED_CURSES_H` is set.
- Adds a GitHub Actions workflow (`solarisvm.yml`) that builds a dist tarball and runs build/test/launch inside a Solaris VM.
- The remainder of the diff is pure whitespace/clang-format reflow (tabs, ternary wrapping, spacing) with no semantic change.

## Release-safety findings
None — safe to release.

Verification performed:
- The `tr_`-rename is complete and consistent: every assignment, call site, and the `terminfo_*` macros in `terminfo-core.h` all use the new `tr_` names. No old member-name accesses remain (`grep` for `->move|->scroll|->clear|->set_fg|...` returns only unrelated `gui->scroll` / `view->scroll` members on other structs).
- `TERM_REC` is internal to `src/fe-text/`; no consumers exist outside that directory, so there is no ABI/API concern for plugins or other modules.
- `TERM_REC` is allocated with `g_new0` in `terminfo_core_init`, so the `term->tr_scroll == NULL` initialization checks in `term_setup` remain valid after the rename.
- The ternary chains that were reflowed (e.g. `tr_set_reverse = TI_rev ? _set_reverse : TI_smso ? _set_standout_on : _ignore`) and the 24-bit color expressions (`last_fg == COLOR_BLACK24 ? 0 : last_fg >> 8`) preserve the original semantics exactly.
- The new meson check is gated on `want_textui && HAVE_TERM_H` and only sets `NEED_CURSES_H` when a bare `term.h` link fails but `curses.h`+`term.h` links. On Linux/glibc/ncurses (the common case), the bare link succeeds, so `NEED_CURSES_H` is not defined and `curses.h` is not pulled in — existing platforms are unaffected. Worst case if the second link also fails is a configure-time `error('could not link terminfo')`, which is a build-time failure on an otherwise-unbuildable platform, not a runtime regression.
- The CI workflow is build-infrastructure only and does not affect the released artifact. It does fetch and execute a script from a third-party repo (`irssi-import/actions-irssi`) inside the VM, but that runs only in CI, not in shipped code.
