# #1611 — Add a muon meson-format GitHub Actions workflow and reformat the meson build files

- Commit: 43f1727e
- Verdict: SAFE

## What it changes
Adds a CI-only meson formatting setup and reformats all build files to match it:
- New `.github/workflows/muon-fmt.yml`: builds muon 0.5.0 from source on Ubuntu, runs `muon fmt -c .muon_fmt.ini -i` over every `meson.build`, then `git diff --exit-code` to fail if anything is unformatted.
- New `.muon_fmt.ini`: muon fmt config (line length 108, 2-space indent, etc.).
- Reformats 33 `meson.build` files to satisfy the formatter.

I tokenized each `meson.build` before and after the change (stripping all whitespace) and diffed the token streams. Across all 33 files the ONLY token-level change is the insertion of trailing commas before closing `)`/`]`: zero tokens removed, zero non-comma tokens added. Trailing commas in arrays and call argument lists are valid in meson, so the build semantics are unchanged. `meson_version` requirement stays `>=0.53`.

## Files touched
- `.github/workflows/muon-fmt.yml` (new)
- `.muon_fmt.ini` (new)
- 33 `meson.build` files (root `meson.build` plus build files under `docs/`, `scripts/`, `src/**`, `tests/**`, `themes/`) — whitespace + trailing-comma reformatting only.

## Release-safety findings
None — safe to release. The build-file edits are pure formatting (trailing commas only) with no semantic change, verified by token-level diff. The two new files (`.muon_fmt.ini`, `muon-fmt.yml`) are CI-only: not referenced by any meson build file and not installed or included in dist, so they have no effect on the released irssi software. The workflow itself sets `permissions: {}` and `persist-credentials: false`, so it has no token/injection exposure; even if it broke, it would only affect CI, not the release.
