# #1577 — Use g_string_free_and_steal to avoid an unused-result warning on GLib 2.76

- Commit: e70993c4
- Verdict: SAFE

## What it changes
Mechanical refactor replacing the idiom

    ret = str->str;
    g_string_free(str, FALSE);

with

    ret = g_string_free_and_steal(str);

across ~18 source files. `g_string_free_and_steal()` (GLib 2.76+) returns the
underlying character buffer and frees the `GString` wrapper — semantically
identical to `g_string_free(str, FALSE)` returning `str->str`, but its return
value is consumed so the new `must-use` warning attribute on `g_string_free`
in GLib 2.76 is no longer triggered.

For GLib < 2.76 the commit adds a compatibility shim:
- `src/core/misc.{c,h}`: an external `gchar *g_string_free_and_steal(GString *)`
  guarded by `#if !GLIB_CHECK_VERSION(2,76,0)`, returning `g_string_free(string, FALSE)`.
- `src/lib-config/write.c`: a file-local `static` copy of the same shim (lib-config
  is a standalone static library that does not include `core/misc.h`).

`src/core/misc.h` is newly `#include`d in the four call sites that lacked it
(`levels.c`, `printtext.c`, `modes.c`, `terminfo-core.c`).

Two call sites deviate from the pure pattern, both correct:
- `src/core/servers.c`: uses `tag = g_string_free(str, FALSE)` directly (return
  value now consumed, so no warning) rather than the helper — harmless inconsistency.
- `src/fe-common/core/fe-messages.c`: inlines `g_hash_table_insert(printnicks, nick,
  g_string_free_and_steal(newnick))`, dropping the separate `g_string_free(newnick, FALSE)`.

`src/fe-common/core/themes.c` also includes an unrelated indentation fixup
(no behavior change).

## Release-safety findings
None — safe to release.

Verification performed:
- Semantic equivalence: `g_string_free_and_steal(s)` == `g_string_free(s, FALSE)`
  (returns the stolen buffer, frees the wrapper). No ownership, double-free, or
  leak change in any converted site, including the empty-GString case (the heap
  buffer is still a valid NUL-terminated `""`).
- Compatibility shim is the canonical implementation and matches GLib's own.
- The `misc.c` shim is external; the `lib-config/write.c` shim is `static`
  (internal linkage). lib-config is a separate static library that does not
  pull in `core/misc.h`, so there is NO duplicate-symbol / ODR conflict when
  building against GLib < 2.76.
- Every `.c` caller has the declaration in scope: the four files that lacked it
  gained the `core/misc.h` include; the rest already had it. No
  implicit-declaration build break on older GLib.
- The two deviating sites (servers.c, fe-messages.c) were checked in full and
  are functionally identical to the prior code.
- No injection, input-handling, or security surface is touched — this is a pure
  allocation-idiom substitution.

## Interactions with related changes
